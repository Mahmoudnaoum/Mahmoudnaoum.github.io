PostHog Product Analytics Setup

An E-commerce Brand

PostHog Product Analytics Event Tracking Funnels

Problem

An e-commerce company had PostHog installed but events were inconsistently named, funnels gave different numbers depending on who built them, and nobody trusted the dashboard. Engineering renamed events without telling anyone, and tracking broke silently until someone noticed the numbers stopped moving.

What I Built

I audited the existing events, created a clean taxonomy with one name per action, rebuilt the SDK setup with proper identification and UTM capture, and set up funnels, session replays, and alerts. Added a reverse proxy so ad blockers don't break tracking. Documented the event structure and set up Slack alerts when key metrics spike or drop.

Result

Clean event naming, working funnels, and alerts that catch issues before Monday. When the checkout funnel dropped 20%, the team got a Slack alert with a replay link showing the error. Engineering knew what broke and where, and fixed it the same day instead of discovering it a week later in a meeting.
